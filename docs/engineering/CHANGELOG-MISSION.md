# Mission changelog

## 2026-10-30 lanes and tiers (P2, ADR 0015)

- A project manifest can carry a `tier` (the bootstrap maturity) and a task a lane (blueprint `size`, or a `Lane:` line). The pair picks the stages from one table (prototype task = implement + verify; production = full pipeline), OpenSpec and analysis only for heavy production tasks, a deterministic brief when plan/brief are skipped, direct verify with one gate repair, and an automatic review for risky results (`assessChanges`). Run input data, so no `patched()` and an unchanged replay fixture. Manifests without a tier keep the full pipeline. Tests: test/lanes.test.ts.

## 2026-10-30 resilience layer (P1, ADR 0016)

- A provider usage limit or a lost connection now pauses the stage on a durable timer and runs it again without using retry attempts (cap 24 hours per stage); Codex error events and Claude `is_error` results are read as errors; a silent Codex run is killed after 15 minutes (45 for build stages) and retried. Behind `patched("provider-pause")`, no replay fixture change. `progress` query shows `paused`. Tests: test/provider-pause.test.ts.

## 2026-10-30 stabilization (P0, B-087 withdrawn)

- The bridge-wide Codex override (`ORCHESTRATOR_FORCE_CODEX`) was removed: Codex cannot run the Unity CLI in its sandbox, so Unity implement rounds changed no files (Cinderfield, task 00e09cd3). Manifests route again (Claude implements). The Unity serial verify then review order and the review-blocker order are now behind `patched()`; tests write to a temporary data directory; the reconcile service logs a waiting finding once per 20 cycles. Plan: docs/engineering/research/orchestration-v2-redesign.md.

## 2026-10-26 Input and output trimming for every stack [B-080..B-083]
- Review digest (B-080): the reviewer used to get the first 60 000 characters of `git diff --binary` sorted by path; in the first game `.utmp/` build output (44% object files, 17% PNG, 4.7% source) filled it and the code never arrived (13 of 16 task diffs were over the cap). `src/diff-digest.ts` lists every changed file, shows source, tests, config and docs in priority order inside a budget, summarises scenes and prefabs, counts generated/binary/lock/.meta files instead of printing them, and shows only the changed files on a follow-up round (hashes per review round in `review-diff-N.json`).
- Stack table (`src/stack-traits.ts`): `detectStack` finds unity, node, jvm, dotnet, python, go and rust from marker files, per folder, so a Unity client next to a Spring Boot server is both. Generated-output, test-file and noise rules are table entries per family; the publish guard, the prefilter and the digest use it (the Unity-only `isGeneratedPath` of the previous PR is replaced). `runCheck` now captures as much stdout as the caller asks for (it silently kept 100 KB).
- Log and trace compactor (B-081): `compactLog` folds framework frames of Java/Kotlin, C#/Unity, Node, Python, Go and Rust, keeps project frames and the cause chain, counts repeats, strips ANSI, timestamps and progress redraws, keeps error lines when it must cut. Gate commands are captured whole (150 000 characters, not the first 5 000: a runner prints failures last), the artifact stores the compacted text (20 000 max), the workflow gets a shorter finding; a pasted trace of eight or more lines in a task is compacted in place at the bridge.
- Agent side (B-082): the Claude allow-list comes from the detected stacks; implement/reproduce agents are told to run long-output commands as `rtk err <command>` when rtk is installed (`ORCHESTRATOR_RTK=0` turns it off); a gate command may declare `report: { format: nunit|junit, path }` and a failure then leads with the list of failing tests (Unity's NUnit report is found from the command).
- Prompt shape (B-083): the implementer's final message has a fixed short shape (REPORT_STYLE); a long summary is cut at review keeping head and tail.
- Bridge: `server.ts` now compacts the prompt; rebuild the container. Not verified live: a Unity or Spring Boot task through these changes.
