# Config schema and precedence (verified 2026-10-22, src/contracts.ts, src/server.ts, src/project-roots.ts)

- **Project manifest** (`ProjectManifestSchema`, zod): id, root/rootEnv/containerRoot, defaultProfile, providers.default, providerRouting[stage]{provider,model,reasoningEffort}, providerTimeouts (<=900000ms), openSpec.enabled, uiUx, qualityCommands / qualityCommandsByProfile (executable enum node|npm|pnpm|yarn), repository{remote,targetBranch,integratedBaseBranch,requiredSourcePaths}, plugins[], policy{maxReviewRounds(1-2),maxRepairAttempts,maxParallelism,requireApprovalBeforeMerge}. No `schema_version` field.
- Loaded by bridge: `ORCHESTRATOR_PROJECT_FILE` (default `project.example.json`) + every `*.json` in `projects/`; duplicate ids fail.
- **Env** (`.env.example`): TEMPORAL_*, ORCHESTRATOR_DATA_DIR/HOST_DATA_DIR/PROJECTS_ROOT/MAX_ACTIVITY_CONCURRENCY/QUEUE_WAIT_ALERT_MS/API_TOKEN, OPENROUTER_API_KEY, PAPERCLIP_*. Not validated at startup (worker reads with `??` defaults; bridge only checks API token).
- **Precedence** for a run: task payload (profile, openSpec flag, approval, test-injection flags) > project manifest > profile defaults (`profiles.ts`) > code defaults. Project root: `rootEnv` env var > `DEMO_PROJECT_ROOT` (default project) > `ORCHESTRATOR_PROJECTS_ROOT`+`root` (must stay inside).
- Gaps: no global config layer; no startup validation of env; test-injection flags (`injectReviewFailure`, ...) accepted from the public API payload (FM-009).

## Additions from the e2e hardening pass (2026-10-22)
- Provider model precedence for CLI providers: manifest `providerRouting.<stage>.model`, then `CODEX_MODEL` (codex only), then the pinned default (`DEFAULT_CODEX_MODEL`). Claude uses the route model only.
- `providerRouting.openspec` is honoured for the OpenSpec proposal, repair and reconcile stages; without it they use Codex.
- Env: `CLAUDE_MAX_BUDGET_USD` (default 10 per Claude stage), `ORCHESTRATOR_WORKFLOW_TIMEOUT_MS` (default 48h), `ORCHESTRATOR_ALLOW_TEST_FLAGS=1` (bridge accepts test-injection flags), `ORCHESTRATOR_BRIDGE_URL` (doctor and e2e driver, default http://127.0.0.1:3101).
- Worker startup now fails fast on an invalid `ORCHESTRATOR_MAX_ACTIVITY_CONCURRENCY` or `TEMPORAL_ADDRESS` (`src/env-validation.ts`).
- Handoff budgets (`HANDOFF_BUDGETS` in `src/handoffs.ts`): planningContext 2800, openSpecDigest 2200, plan 900, brief 1200 (hard ceiling 1800), reviewChecklist 900; invariants are unit-tested.

## Analysis stage and manifest aliases (2026-10-23)
- Manifest `analysis`: `{ enabled: boolean (default false), docsDir: relative path (default docs/analysis) }`. A task line `Analysis: on|off` overrides `enabled` (parsed by `parseTaskDirectives`, together with `OpenSpec: on|off`). Route: `providerRouting.analyze`.
- Manifest `aliases`: readable alternative ids; the id is normally the Paperclip project UUID. `GET /health` lists ids and aliases; the bridge resolves either.
- New handoff budgets: `analysis` 1400 tokens, `planningContext` 3600, `brief` 1700 (hard ceiling 2550).

## Quality gate severity and visual verification (2026-10-23, ADR 0007)
- `qualityCommands[].severity`: `"fail"` (default, run stops) or `"warn"` (a failing command becomes a warning in the final message). Use `warn` to adopt knip or jscpd without blocking work; same executables as before (node, npm, pnpm, yarn).
- Manifest `visual` (optional, default off): `{ enabled, command: {executable, args, cwd?}, url (http://localhost, 127.0.0.1 or [::1] only), readyTimeoutMs (default 60000), viewports [{name,width,height}] (1 to 3, default desktop 1280x720), steps (1 to 40 of press{key} | wait{ms<=10000} | click{selector} | shot{name}), maxImages (default 6, max 8), required (default false) }`.
- Behaviour: during the review activity the app is started in the task worktree, screenshots are taken with `playwright-core` driving an already installed Chromium, and the images go to the reviewer (Codex via `--image=`; other providers get the file paths). Any capture problem is a warning; `required: true` fails the review instead. Screenshots live under the run artifacts, never in the repository.
- Browser discovery: `ORCHESTRATOR_BROWSER_PATH`, then the newest Playwright download (`PLAYWRIGHT_BROWSERS_PATH` or the default cache), then system Edge or Chrome. `npm run doctor` reports `visual:browser` for projects that enable it.

## Task types (2026-10-23, ADR 0008)
- Request fields (`POST /v1/runs`): `taskType` (task|bug|research|architecture and aliases), `labels` (Paperclip label names; the adapter fills it from `issue.labels`). Precedence: `taskType` > labels (`type:bug`, `kind: research`, bare `bug`, `spike`, ...) > a `Type: bug` line in the task text > agent profile (`bugfix` -> bug, `research` -> research). Conflicting labels are rejected. No type: the original pipeline for the profile.
- Types map to profiles: task -> `implementation`, bug -> `bug` (delivery stages after the investigation), research and architecture -> `investigation` (no delivery stages; ends in a document).
- Manifest `documents`: `{ researchDir: relative path (default docs/research), architectureDir: relative path (default docs/architecture) }`. Bug diagnoses are committed under `analysis.docsDir` as `<task>-diagnosis.md`.
- New stage names usable in `providerRouting` and `providerTimeouts`: `diagnose`, `reproduce` (the only investigation stage that may write files, and only tests), `scope`, `explore`. Defaults: 15, 20, 5, 20 minutes. Missing routes use the project default provider.
- `qualityCommandsByProfile` is looked up by task type, then delivery profile (`bug`), then the agent's profile name (`bugfix`), then `qualityCommands`. Bug and task types need quality commands for real providers; research and architecture do not.
- Research and architecture with a real provider need `repository` (the report is a draft PR). Bug runs do not use OpenSpec unless `OpenSpec: on` is written in the task.
- Reproduction commands chosen by the model are limited to: `npm|pnpm|yarn test [-- args]`, `... run <script>`, `node --test <path>`, `node <relative script>`; no inline code, preload or loader flags, no absolute or parent paths (`reproductionCommandProblem`).
- `RunResult.status` may be `needs_info`; `RunResult.report` carries the markdown of research and architecture runs; `RunResult.metadata.taskType` records the type.

## Project bootstrap (2026-10-23, ADR 0009)
- Task type `bootstrap` (label `type:bootstrap`, aliases `new-project`, `project-setup`). The form is a hidden `<!-- bootstrap-form {json} -->` block in the Paperclip task description; `BootstrapFormSchema` (`src/bootstrap-options.ts`) validates it: name, description, `options` (only values the user set), optional `repoName` and `repoOwner`, and the Paperclip ids (company, project, agent).
- Options come from one catalog (`OPTION_CATALOG`), served at `GET /v1/bootstrap/catalog` and resolved at `POST /v1/bootstrap/resolve`. Precedence per option: the user's value, then the preset of the chosen maturity (`PRESETS`), then the catalog default; platform rules then derive values and mark them `derived`. Provenance (`user`, `preset`, `default`, `derived`) is kept and written into the generated contract.
- Global file `bootstrap.global.json` (override path with `ORCHESTRATOR_BOOTSTRAP_CONFIG`; missing file means built-in defaults, an invalid file is an error): `stages` routes for `stack`, `charter`, `blueprint`; `manifest` defaults copied into every generated manifest (`providers`, `providerRouting`, `providerTimeouts`, `containerProjectsRoot`, `targetBranch`). The bridge reads it from `/app/bootstrap.global.json` (compose mount); the worker reads it from the repository root.
- `bootstrap.global.json` `contract` (ADR 0011): `file` (relative path inside the repository, default `docs/PROJECT_CONTRACT.md`), `maxChars` (1500..20000, default 6000) and `rules` (at most 12 global drift rules of at most 300 characters; default four). The rules are written into every generated contract and, with the contract file read at the task's base commit, form the `RunInput.projectContract` block of the plan, implement and review prompts. Precedence: global rules, project contract, task text. A repository without the file gets no block. The bridge re-reads the file at every task start (see runbook section 6 for the single-file bind-mount caveat).
- Option `plan_mode` (`sequential` default, `parallel`; delivery group, advanced): in a parallel plan the declared `depends_on` become the Paperclip blockers. `RepositoryContext.integrateParents` (set by the bridge when a task has several blockers and the manifest has no `repository.integratedBaseBranch`) makes the worker build `integration/<task branch>` from the blockers' published branches.
- Generated manifests are written by the worker to `projects/generated/<paperclip-project-uuid>.json` (git-ignored). The bridge reads `projects/*.json` and `projects/generated/*.json`, and re-reads them once when it meets an unknown project id.
- New stage names for `providerRouting` and `providerTimeouts`: `stack`, `charter`, `blueprint` (defaults 10, 10, 15 minutes).
- Worker env used by the bootstrap steps: `ORCHESTRATOR_PROJECTS_ROOT` (where the project folder is created), `ORCHESTRATOR_PROJECTS_DIR` (manifest folder, default `projects`), `PAPERCLIP_API_URL` and `PAPERCLIP_API_TOKEN` (create the tasks), and the machine's `gh` login (create the repository).
- Plugin settings (per company, in Paperclip): `bridgeUrl` (default `http://orchestrator:3101`) and `bridgeToken` (a Paperclip secret holding `ORCHESTRATOR_API_TOKEN`).
- `RunResult.bootstrap` records the repository URL, local folder, commit, manifest path, template, whether the scaffold was verified, warnings and the created issues.

## Stack profiles, Unity and games (2026-10-24, ADR 0012 and 0013)
- Manifest `stack`: `{ profile: "node-web" | "unity-mobile" (default node-web), unity: { editorVersion (e.g. 6000.3.11f1), executeMethods: ["Class.Method"] (at most 10) } }`. Optional; absent means node-web. Quality commands may use executable `unity` only with `unity-mobile`, as `unity test|build|recompile` with the CLI's flags (no `--`, `--args`, `--editor-path`, `--allow-install`, `--accelerator`, `--proxy`; `--execute-method` only for a declared method). `visual.engine: "unity"` needs `unity-mobile` and `visual.unityFilter`.
- Manifest `visual`: `engine` ("web" default | "unity"), `command` and `url` are required for web only, `unityFilter` for unity; `readyTimeoutMs` max is now 1,800,000 (Unity captures wait for an Editor run).
- Stage name `design` (game design): usable in `providerRouting`, `providerTimeouts` and `bootstrap.global.json` `stages`; default timeout 15 minutes.
- Options: `product_kind` (app|game), `engine` (auto|unity), `game_orientation`, `game_art`, `game_fps`. A game derives `platform` mobile_android (from web, cli or api), `engine` unity, `architecture` frontend_only and at least unit tests.
- Env: `ORCHESTRATOR_WORKTREES_DIR` (short worktree folder), `UNITY_AGENT_PLUGIN_DIR` (checkout pinned by `npm run unity:plugin`), `UNITY_EDITOR_PATH`, `UNITY_EDITORS_ROOT`, `UNITY_IMPORT_TIMEOUT_SECONDS`, `ORCHESTRATOR_TEMPLATES_DIR`.
- Templates live in `templates/<id>/` and are copied by the scaffold with `{{NAME}}`, `{{PACKAGE}}`, `{{ORIENTATION}}`, `{{FPS}}` replaced.
