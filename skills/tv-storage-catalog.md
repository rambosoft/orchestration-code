Use four storage levels: hot memory for visible data, bounded warm memory for nearby data, IndexedDB for catalogues, indexes, and preferences, and the remote source. Bound and evict caches; set TTLs by data class; index queries; migrate schemas; deduplicate and cancel requests; recover from quota and storage errors; record metrics; invalidate targeted data; define offline behavior; isolate by provider, account, and profile. Never treat incomplete imports as complete or let a failed refresh destroy usable data. Avoid localStorage for catalogues and frequent writes. For large catalogues, keep items out of unbounded memory and the DOM: page or fetch categories where supported, virtualise with bounded overscan, normalise and index metadata in IndexedDB, use indexed search, prefetch by navigation pattern, cancel stale requests, deduplicate, and apply back-pressure under rapid input. A whole-list provider response cannot be avoided client-side; use discovery to decide whether an indexing proxy is needed.
